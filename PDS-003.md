# 1 Purpose

This document defines every primitive that exists inside PuzzleDSL.

No implementation may invent new primitives.

No LLM may generate primitives outside this document.

Every primitive has

• Identity

• Parameters

• Validation

• Rendering Behaviour

• Composition Rules

---

# 2 Primitive Philosophy

PuzzleDSL follows one rule.

Questions are never stored.

Questions are BUILT.

Exactly like LEGO.

Question

↓

Primitive

Primitive

Primitive

↓

Composition

If a question cannot be represented,

The language evolves.

The renderer does not.

# 12 Acceptance Tests

The Primitive Standard Library is complete only if

✓ Every official dMAT question uses only defined primitives.

✓ No primitive performs rendering.

✓ No primitive requires browser information.

✓ Every primitive serializes to JSON.

✓ Every primitive is deterministic.

✓ Every primitive has exactly one responsibility.

✓ Every primitive belongs to exactly one category.

If any condition fails,

The library is incomplete.
