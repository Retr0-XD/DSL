# 1 Purpose

The purpose of this document is to define the reasoning model used by dMAT.

PuzzleDSL SHALL NOT generate pictures.

PuzzleDSL SHALL generate reasoning problems.

The renderer visualizes those reasoning problems.

Therefore the reasoning model is the highest level of abstraction.

---

# 2 Philosophy

Every puzzle is composed of

Objects

↓

Properties

↓

Transformations

↓

Rules

↓

Inference

The student never solves pictures.

The student solves transformations.

---

# 3 Question Anatomy

Every question consists of five layers.

Observable State

↓

Hidden Rule

↓

Rule Interaction

↓

Prediction

↓

Verification

The hidden rule is the actual puzzle.

Everything else only exposes clues.

---

# 4 Primitive Reasoning Operations

PuzzleDSL recognises only the following primitive reasoning operations.

Movement

Rotation

Reflection

Translation

Alternation

Symmetry

Counting

Comparison

Replacement

Scaling

Insertion

Deletion

Grouping

Ordering

Dependency

Progression

Transformation

Visibility

Every future question MUST be reducible to these operations.

---

# 5 Composite Reasoning

Real dMAT questions rarely contain one primitive.

Instead they combine multiple primitives.

Example

Rotation

+

Movement

+

Colour Alternation

↓

Composite Rule

Difficulty increases by interaction complexity rather than primitive count.

---

# 6 Hidden Rule

Every question SHALL contain exactly one primary hidden rule.

Additional rules are secondary.

Primary Rule

The minimum reasoning required.

Secondary Rule

Supports or distracts.

Questions with multiple unrelated primary rules are forbidden.

---

# 7 Observable Variables

The following variables may change.

Position

Rotation

Colour

Shape

Size

Visibility

Text

Direction

Count

Relationship

Nothing else shall change without introducing a new DSL version.

---

# 8 Constant Variables

Every puzzle also contains constants.

Grid

Object Identity

Frame Count

Question Goal

Answer Format

These remain fixed.

---

# 9 Difficulty Model

Difficulty SHALL be computed from weighted components.

Reasoning Layers

Rule Interaction

Visual Noise

Distractor Quality

Inference Distance

Working Memory Requirement

Temporal Reasoning

Difficulty SHALL NOT depend on

Object count alone

Grid size alone

Colour count alone

---

# 10 Cognitive Load

Every puzzle receives a Cognitive Load Score.

Factors

Objects

Rules

Frames

Transformations

Branches

Hidden Dependencies

Renderer never displays this score.

Used for generation only.

---

# 11 Reasoning Depth

Depth

1

Single observation

↓

Depth

2

One transformation

↓

Depth

3

Transformation chain

↓

Depth

4

Multiple interacting rules

↓

Depth

5

Multi-stage inference

Version 1 SHALL support Depth 1–4.

---

# 12 Rule Independence

Independent Rules

Can be solved separately.

Dependent Rules

Require previous rules.

Mutually dependent rules are forbidden.

---

# 13 Distractor Design

Wrong answers SHALL satisfy one of the following.

Correct rule but wrong step.

Correct movement but wrong rotation.

Correct transformation but wrong order.

Partial application.

Previous frame.

Next frame.

Random distractors are forbidden.

---

# 14 Ambiguity

A puzzle is ambiguous if

Multiple rules explain observations equally well.

Such puzzles SHALL be rejected.

---

# 15 Novelty

Generated puzzles SHALL avoid excessive similarity.

Similarity SHALL be measured using reasoning signatures.

Renderer appearance SHALL NOT be used.

---

# 16 Reasoning Signature

Every question generates a signature.

Example

Movement:CLOCKWISE

Rotation:90

Colour:ALTERNATE

Frames:5

Depth:3

This signature is used for duplicate detection.

---

# 17 Learning Objectives

Every generated question SHALL target exactly one learning objective.

Examples

Boundary movement

Alternation

Rotation

Composite reasoning

Symmetry

Working memory

Hidden dependency

Learning objectives SHALL be explicit.

---

# 18 Coverage

Generation engine SHALL track coverage.

Example

Rotation

72 Questions

Reflection

5 Questions

System SHALL encourage underrepresented reasoning operations.

---

# 19 Rule Library

Every reasoning operation SHALL belong to a central Rule Library.

Rule Library contains

Definition

Parameters

Examples

Difficulty Contribution

Compatible Rules

Incompatible Rules

Validation Rules

No question shall invent a new rule outside the library.

---

# 20 Question Fingerprint

Every question receives a fingerprint.

Fingerprint =

Reasoning Signature

+

Difficulty

+

Learning Objective

+

Rule Sequence

Questions with identical fingerprints SHOULD be avoided.

---

# 21 Validation

Every generated question SHALL satisfy

One primary rule

Deterministic reasoning

Unique answer

No ambiguity

Consistent transformations

Valid distractors

Meaningful learning objective

Reasoning signature generated

Coverage updated

---

# 22 Acceptance Tests

The Reasoning Model is accepted only if

✓ Every official dMAT question can be described entirely using the reasoning model.

✓ Every generated question produces a reasoning signature.

✓ Duplicate detection works without comparing rendered images.

✓ Difficulty can be estimated before rendering.

✓ Learning objectives are explicit.

✓ The renderer has zero knowledge of reasoning.

If all conditions pass,

The dMAT Reasoning Model is accepted.
