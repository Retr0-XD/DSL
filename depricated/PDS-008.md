# 1. Purpose

This document defines the Canonical Question Specification (CQS).

CQS is the ONLY format used inside the system.

Every question, regardless of type, SHALL exist as one CQS document.

Examples

Figure Sequence

↓

CQS

Latin Square

↓

CQS

Mathematical Equation

↓

CQS

Subject Module

↓

CQS

There are no separate formats.

There is exactly ONE question format.

------------------------------------------------------------------------------

# 2. Design Goals

CQS shall satisfy all of the following.

✓ Human readable

✓ LLM writable

✓ Easy to diff in Git

✓ Version controlled

✓ Deterministic

✓ Extensible

✓ Render independent

✓ Framework independent

------------------------------------------------------------------------------

# 3. Repository Structure

The repository SHALL follow exactly this structure.

repository/

├── schemas/

├── renderer/

├── validator/

├── prompts/

├── knowledge/

├── generators/

├── questions/

│      ├── figure-sequence/

│      ├── latin-square/

│      ├── mathematical-equation/

│      └── subject/

├── fingerprints/

├── assets/

└── docs/

Any deviation must be documented.

# 20. CQS Rules

Every question SHALL satisfy

Exactly one answer

Exactly one primary reasoning rule

Deterministic rendering

Valid fingerprint

Unique ID

Version number

Review status

------------------------------------------------------------------------------

# 21. CQS Versioning

Major Version

Breaking changes

Minor Version

Backward compatible additions

Patch

Metadata only

Renderer SHALL support all patch versions.

------------------------------------------------------------------------------

# 22. Implementation Rules

The implementation SHALL

Load only CQS.

Never modify CQS during rendering.

Never generate new fields.

Reject malformed CQS immediately.

------------------------------------------------------------------------------

# 23. Forbidden Practices

Do NOT

Store HTML

Store SVG

Store CSS

Store React Components

Store JavaScript

Store Images

Store Base64

Store Binary Data

Store Rendered Screenshots

Everything must remain declarative.

------------------------------------------------------------------------------

# 24. Acceptance Criteria

The implementation is accepted only if

✓ Every supported question family uses identical CQS.

✓ Renderer consumes only CQS.

✓ Validation consumes only CQS.

✓ Prompt builder consumes only CQS.

✓ Repository stores only CQS.

✓ Git diff is human readable.
