# 1 Purpose

This document defines the canonical Question Object Model.

The Question Object Model (QOM) is the ONLY structure an LLM shall produce.

PuzzleDSL is generated from the QOM.

The compiler SHALL NOT receive raw LLM text.

The renderer SHALL NEVER receive the QOM.

The data flow SHALL always be

LLM

↓

Question Object Model

↓

PuzzleDSL

↓

Compiler

↓

Puzzle Render Tree

↓

Renderer

---

# 2 Why QOM Exists

Weak language models struggle to author programming languages.

They perform significantly better when filling structured forms.

The Question Object Model is therefore designed to resemble a structured questionnaire rather than source code.

---

# 3 Design Goals

The QOM SHALL be

Human Readable

Machine Readable

Machine Writable

Framework Independent

Language Independent

Self Validating

Composable

Versionable

---

# 4 One Question = One Object

Every question SHALL be represented by exactly one Question object.

Nested Question objects are forbidden.

---

# 5 Question Object

Every Question SHALL contain exactly these sections.

metadata

problem

entities

rules

interaction

solution

explanation

quality

No additional top-level fields are permitted.

# 21 Quality Rules

The Question Object SHALL satisfy

Exactly one solution

No missing entities

No duplicate IDs

No undefined references

No impossible actions

No unreachable answer

No renderer information

---

# 22 Forbidden Information

The QOM SHALL NEVER contain

HTML

SVG

CSS

JavaScript

Canvas

Browser APIs

Framework names

Pixel coordinates

Images

Base64

Binary

Markdown

Prompt text

---

# 23 LLM Contract

The LLM SHALL

Only produce QOM.

Never produce PuzzleDSL.

Never produce HTML.

Never produce SVG.

Never produce renderer instructions.

If a field is unknown,

Generation SHALL fail.

Guessing is forbidden.

# 24 Validation Pipeline

QOM Validation

↓

PuzzleDSL Generation

↓

Grammar Validation

↓

Compiler

↓

Timeline Generation

↓

Render Tree

↓

Renderer

Failure at any stage rejects the question.

---

# 25 Acceptance Tests

The QOM is accepted only if

✓ Every supported question type can be represented.

✓ No renderer knowledge exists.

✓ No implementation details exist.

✓ Weak language models can author valid questions.

✓ QOM serializes to JSON.

✓ QOM converts deterministically into PuzzleDSL.

If every condition passes,

Question Object Model Version 1 is accepted.
